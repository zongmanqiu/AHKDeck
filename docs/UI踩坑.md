## K1–K51 硬规矩与踩坑

| # | 现象 | 正解 |
|---|---|---|
| K1 | 两个按钮全哑、只有拖放能用 | `GWL_ID(-12)` 是**控件 ID**，`GWL_STYLE` 才是 `-16`；AHK 靠 `WM_COMMAND` 的控件 ID 派发 Click，写坏 ID 即永不触发。别手写 GWL 样式位「美化」 |
| K2 | 主题美化毫无效果 | `SetThemeAppProperties` 在 **uxtheme.dll** 不在 user32；且 `0x7` 本就是默认允许主题，调了也没用 |
| K3 | 强调色/灰字不生效 | `GuiCtrl` **没有 `.Color` 属性**，赋值静默无效；颜色只在 `Add` 的 `Background` / `c` 选项里给 |
| K4 | 「选择文件」按钮像坏了 | `FileSelect(&sel, , 标题)` 三参把标题当 RootDir，目录不存在则静默 false；必须四参 `(&sel, Options, RootDir, Prompt)` |
| K5 | 输入框/列表有 3D 凹陷边 | AHK 默认给 Edit/ListView/ListBox/TreeView 加 `WS_EX_CLIENTEDGE`（`script_gui.cpp:2938/2950/2960/2964`），`exstyle = add & ~remove`（`:3093`）→ `-E0x200` 抵消；别用 `+Border` 或手写样式位 |
| K6 | 输入框文字贴顶 | `EM_SETRECT(0xB3)` 对**单行**无效、对 `ES_MULTILINE` 线性生效；`Multi` 会自动附 `WS_VSCROLL\|ES_WANTRETURN\|ES_AUTOVSCROLL`（`:3152-3155`），必须 `-VScroll -WantReturn` 去掉，`-Wrap` 加回 `ES_AUTOHSCROLL` |
| K7 | 列表框比表头宽一点 | 边框底块与列头/按钮同 x/y/w/h，原生控件内缩 1px；外扩 1px 就会宽出去 |
| K8 | `#Include` 找不到文件 / 想抽公共 UI 库 | `#Include` 是预处理指令，不能用 `A_ScriptDir` 等变量；且分发模型禁止共享库（§10.1） |
| K9 | 双击复制偶发参数错误 | `ListView.GetNext(0, "Selected")` 非法，RowType 只认 `F` / `C` / 空 → 用 `GetNext(0)` |
| K10 | 面板一关脚本就「崩了」 | 内核 `Script::IsPersistent()` 只认六种常驻凭据；往 `A_TrayMenu` 加项、`OnMessage` 都不算。只有托盘入口 + 弹窗面板要写 `Persistent(true)` |
| K11 | 标题栏没变色 / 读不到颜色 | DWM 属性 35=底色 / 36=标题文字 / 34=边框，**只写不支持读**（读取返回 `E_INVALIDARG`），验证只能看像素；Win10 不支持时静默降级。关掉进程主题会让 caption 降级、DWM 色失效 |
| K12 | `Invalid option: x%d` | AHK v2 `Format()` 用 `{1}` 占位符，不是 `%d` |
| K13 | 发消息后卡死 | 往 AHK 脚本窗口发 `SendMessage`/`PostMessage` **命令**会死等（MsgMonitor 跨进程同步回调）；发送侧必须 `DllCall("PostMessageW", ...)` 直调 Win32 |
| K14 | DateTime 显示成一串数字 | `Gui.Add("DateTime", opts, 第三参)` 第三参是**显示格式串**不是初始值；`.Value` 恒 14 位；去下拉用 `+0x1`（DTS_UPDOWN） |
| K15 | 跨进程找不到窗口 / 状态条颜色不对 | AHK v2 主窗口类名是 `#32770`（对话框类），v1 才是 `AutoHotkey`，只按 `ahk_pid` 匹配；原生 `StatusBar` 没有 `.Value`（用 `.SetText()` / `.Text`），Win11 下 `Background` 需 `-Theme`，要精确同色就改回 `Text` 色块 |
| K16 | 勾选框永远是经典黑勾 + 3D 方框 | 系统 `CheckBox` 自绘，样式位只影响外框、改不了勾与底色。用 §10.5 的 `class FlatCheck` 三层 `Text` 色块；勾形用 `✓` + `s11 Bold`（`√` 太细、`✔` 太糊） |
| K17 | DateTime 去边框后仍有一圈深灰立体边、按钮还是 3D 的 | `SysDateTimePick32` 的边框与右侧按钮都是**控件内绘**，`WS_BORDER` 只是其中一层。正解是裁到只剩文字区（`ClipField`，日期与时分秒都裁到 115），按钮改用 `Text` 色块并把点击按原生按钮坐标 `Post` 回去 |
| K18 | 加载时弹出「This line will never execute」且 `/validate` 卡死 | AHK v2 的 `class` / 函数体外的可执行语句**不会提升**：类声明写在顶层 `return` 之后就永不执行，还会弹模态框（连 `/validate` 都被挡住）。类必须定义在使用它的 auto-execute 代码之前 |
| K19 | 自绘色块收不到点击，`OnMessage(0x201)` 里的 `hwnd` 全是主窗口 | 静态控件不加 `SS_NOTIFY`（`+0x100`）时对命中测试返回 `HTTRANSPARENT`，鼠标点击穿透到父窗口。凡是靠 `OnMessage` 取 `hwnd` 分派的色块，都要 `+0x100` |
| K20 | 滑块明明是深色却整条显示成槽色、点上去还当成轨道 | 色块的叠放谁在上由 z 序决定，宿主里 `SetWindowPos(..., HWND_TOP, ...)` 返回 1 也压不住。别做叠放：轨道拆成滑块前 / 后两段，几何上永不重叠 |
| K21 | 关掉窗口后弹「The control is destroyed」 | 定时器会让脚本在 `Gui.Destroy()` 之后继续存活，下一拍就去碰已销毁的控件。关闭事件里先 `Stop()`（停掉 Sync/DragTick、释放捕获）再 `Destroy()` |
| K22 | 自绘滚动条做好了，原生条却和它一起出现（两条并存） | `ShowScrollBar(false)` 能藏住原生条，但它会顺带**摘掉** `WS_HSCROLL`/`WS_VSCROLL` 样式位（见 K29）。隐藏动作要放在会重算滚动范围的动作（`Move`/`Add`/`Delete`/`ModifyCol`）**之后**，并在 `Sync` 每拍按样式位兜底 |
| K23 | 滑块做窄之后，槽在滑块那一段被切成两截、两侧露出窗口底色 | 槽本来是「滑块前 + 滑块后」两段，滑块一窄，那一段的两侧就没有色块了。补两条与滑块同长的同色细缝（左右 / 上下各一条，宽 = 内缩量），四块沿轴相邻即可，不要改成叠放 |
| K24 | 拖动滑块时出现断块、停下还留着孤立的小方块 | 一次重排里的 8–11 个色块逐个 `Move`，屏幕上会出现「槽已让位、滑块还没到」的中间帧；拖动 20ms 一拍，中间帧就被看见并被截进图里。用 `BeginDeferWindowPos`/`DeferWindowPos`/`EndDeferWindowPos` 一次提交全部位置；同时 `Sync` 在拖动中只兜原生条、不要重复 `Paint`（会和 `DragTick` 同一帧交叉） |
| K25 | 两个按钮各自很宽、文字两侧空一大片 | 按钮宽度是按「铺满这一行剩下的宽度」倒推的（100/104），可 s10 四个字只有 52px 宽。宽度改成「文字 + 左右各 16」，整组右对齐；行内有弹性控件就让它吃余量，没有就把余量留在按钮组左侧 |
| K26 | 浅色方案里按钮「看不出是按钮」 | 底色只到 `BAND` 一档时，按钮和色带同色，只靠文字没有任何按钮感。改「外块描边色 + 内块缩进 1px」两层结构，一律 `FRAME` 边 + `SOFT` 底；两层都要挂 `Click`，否则 1px 边上点不动。主次不要用颜色分 —— 中蓝边配近黑字发闷 |
| K27 | 带标题的列表区看着「框线没把标题包住」 | 标题带自铺一条 `BAND`、`ListView` 又靠父块露 1px 边框，两条边各自成立，读起来像一块色条压在一个框上。外框块从标题带**顶边**起、标题带与列表都内缩 1px 落进同一个框；别让两者各带各的边 |
| K28 | 自绘按钮想做悬停变色，宿主里怎么改都不显示 | 宿主内脚本 GUI 的运行期重绘不受控，四条路全堵：①`Opt("Background")` 改静态控件底色 —— 独立运行有效（还要补 `InvalidateRect`），宿主里改完不重绘，`InvalidateRect` / `UpdateWindow` / `RedrawWindow(0x0181)` 全试过，截图仍是常态色；②叠一层同尺寸悬停色块 —— 显示后仍被常态层盖住，`SetWindowPos(HWND_TOP)` 压不住（同 K20），连初始可见都只在后建的那一枚上生效；③换层（藏常态、显悬停层）—— 显隐都成功（`IsWindowVisible` 1↔0），但被藏掉那块区域宿主不重绘，像素停在旧色；④`SWP_FRAMECHANGED` 同样无效。结论：**宿主内不给自绘按钮加悬停**。鼠标消息本身能收到（落在外层描边块上，说明外层色块压在文字层之上），卡的是「画」 |
| K29 | 自绘滚动条藏掉原生条之后，滚轮完全不滚、键盘翻页也没反应 | `ShowScrollBar(FALSE)` 会**摘掉** `ListView` 的 `WS_VSCROLL`/`WS_HSCROLL`：摘掉后 ListView 不再处理 `WM_MOUSEWHEEL`（实测首行号纹丝不动）、不再处理翻页键，滚动范围也塌成 0（`GetScrollInfo` 全 0）。正解：**不要依赖原生滚动状态**，行数 / 可视行数 / 首行号自己维护，滚动走 `LVM_ENSUREVISIBLE`（摘掉样式位后依然精确到位），滚轮与翻页键用 `OnMessage` 接管。滚轮消息只发给**焦点**控件，焦点在输入框时列表收不到，所以按「窗口内任意控件」处理 |
| K30 | 横向滚动条画出来了却拖不动 | 横向 `LVM_SCROLL` 实测完全不生效（有无样式位都不行），而且 `wParam` 传的是 `delta` —— 那里应该是 `SB_HORZ`（0），`lParam` 才是像素增量。横向条一直是装饰品：**撤掉横向条，列宽做进视口**（列宽和 = 列表可视宽），需要看全的字段另想办法 |
| K31 | 最大化再复原后，列表右侧留一大块白 | `ListView` 改列宽后，行底色的绘制范围会停在**旧列宽**的位置（实测条纹长度由满宽 1023px 缩到 478px，复原后也不恢复）。改完列宽必须 `S.lv.Redraw()` 整表重绘；`InvalidateRect`+`UpdateWindow`、调换 `ModifyCol` 与 `Move` 的顺序都无效 |
| K32 | 把回调存进对象属性后写成 `this.cb(v)` 调用，一点就崩 | AHK v2 里 `this.cb(v)` 会把 `this.cb` 当成**方法**调用，隐式多传一个 `this`，于是报「Too many parameters passed to function」——官方解释器弹错误框、宿主内核直接终止整个进程。正解：显式 `this.cb.Call(v)`（`.Call` 对函数对象是显式调用，不带 this）。官方 2.0.30 与宿主内核（官方 2.0.31 + 门控补丁）**行为一致**，不是宿主特有。受影响：`FlatTrack`（夜灯）、`FlatCheck`（文件时间修改）。这类 bug 只有**真的点一下**才暴露 —— 「能打开、能显示」的截图验不出来，必须用真实鼠标点击 + 检查错误框/进程存活 |
| K33 | 自绘滑块拖动后留下残影 / 一道旧位置的白影 | 滑块比槽高时（本例 20 vs 10），它上下各溢出几 px；滑块移开后腾出的那几条属于**窗口背景**而不是任何控件，宿主不重绘这块区域，旧像素就留在屏幕上。两件事一起做：① 在滑块下方铺一条与滑块**同高**的同色底衬，让腾出的像素归属一个会正常重绘的静态控件；② 外框与内块用 `BeginDeferWindowPos`/`DeferWindowPos`/`EndDeferWindowPos` 一次性提交，别逐个 `Move`（否则还有「外框已到、内块还在旧位」的中间帧，同 K24） |
| K34 | 列表滚动一次之后，右侧又冒出一条原生滚动条 | `LVM_ENSUREVISIBLE`（滚动定位）会让 ListView 重算滚动范围并把 `WS_VSCROLL` **重新置回**，原生条于是露出来（实测滚动后右侧出现 16px 的 `F0F0F0`）。不能只靠 `Sync` 的 60ms 兜底 —— 每次滚动动作（`ScrollToRow`）结束后必须当场再调一次 `HideNative()` |
| K35 | 窗口拉窄后，工具行的搜索框不变窄、右侧按钮被窗口边缘裁掉 | 工具行如果全用绝对坐标建出来，`OnGuiSize` 又只重排列表与状态条，工具行就纹丝不动（1100 宽的版式塞进 820 宽的窗口，右侧按钮整个跑到窗口外）。工具行要分三段：左侧固定按钮、**右侧按钮贴右缘**、中间弹性控件吃余量，在 `OnGuiSize` 里按客户区宽重算。另注意 `FlatButton` 是「外框 + 内块」两层，返回的只有内块，重排时两层都要挪，否则外层留在原地露出旧边 |
| K36 | 刚打开窗口时右侧闪出原生滚动条（而且不是一帧） | 核心事实：**`WM_SETREDRAW` 只压得住客户端绘制，压不住非客户区滚动条**。行一多 comctl32 就把 `WS_VSCROLL` 置回并当场把条刷出来；竖条让客户区窄 16px，按整幅宽算好的列宽立刻溢出，横条跟着再冒一条 —— 屏幕上就是「空列表 + 两条原生灰条」。而且填充是长任务（实测 1813 行 718ms），期间单线程没有空闲，60ms 的 `Sync` 定时器根本挤不进来，「事后补一刀」只能擦掉最后一帧。**正解是填表期间直接 `ShowWindow(lv, SW_HIDE)`**（隐藏窗口一个像素都不画），填完摘条 → `WM_SETREDRAW 1` → `SW_SHOW` 一次整幅重绘；`SW_HIDE` 会丢焦点，要捕获 `Gui.FocusedCtrl` 后补 `Focus()`。验收必须在**宿主里逐帧采样整窗**，且采样带要用 `GetWindowRect`——`GetClientRect` **不含**滚动条，按它算会整整错开 16px，看着「0 命中」其实条就在旁边 |
| K37 | 类型名（如 `.txt` 的 `txtfile`）显示成一段没见过的中文 | 不是编码问题，是**取数口错**：`HKCR\<ProgID>` 的默认值不是 Shell 显示类型名用的字段，还可能被旧软件写脏（实测本机该值是「文本文档」的 UTF-8 字节按 GBK 写进 `REG_SZ`，读出来是 `鏂囨湰鏂囨。`）。按可信度取：MuiCache → `FriendlyTypeName`（`@C:\Windows\system32\shell32.dll,-30598` 这类间接串用 `shlwapi\SHLoadIndirectString` 解成本地化名称）→ 默认值只作兜底 |
| K38 | 以为「60ms 定时器会兜底」，结果长任务期间它一次都没跑 | AHK 是单线程：脚本卡在 `FillList` / 扫描这类同步块里时没有空闲，`SetTimer` 的回调**不会**插进来。实测填 1813 行耗 718ms，60ms 的 `Sync` 只在收尾挤进两拍（1110ms 进、1828ms 出）。凡是「事后补一刀」的清理动作，必须放进**同一个同步块内**、排在所有会触发重算的动作之后；定时器只适合处理「用户操作之间」的空闲态（滚轮、拖动、窗口缩放） |
| K39 | 用 `SW_HIDE` 藏控件之后，键盘操作全哑了 | 隐藏会丢焦点，`Delete` / 翻页键不再进列表。隐藏前记 `hadFocus := S.gui.FocusedCtrl && S.gui.FocusedCtrl.Hwnd = lv.Hwnd`，显示后补 `lv.Focus()`；本来就没焦点（启动后第一次填表）时也顺手给它，省得用户还要先点一下。控件级「临时藏一下」= `ShowWindow(hwnd, 0)` / `(hwnd, 5)`，不是 `Gui.Hide()` |
| K40 | 门禁一直绿，肉眼却明明看得见灰条 | 采样带按 `GetClientRect` 算 —— 客户区**不含**滚动条，采样带整整错开 16px，正好避开那 16 列，于是「0 命中」。改用 `GetWindowRect`（含非客户区）。教训升级：**新写的检查项必须拿修复前的版本跑一次，确认它会红**（见「取证方法学」） |
| K41 | 报「闪一下」，修了两版还是闪 | 先量清楚是「一帧」还是「一段」。逐帧采样给的是**时间区间**：修前 `1203→2054ms` 连续约 850ms —— 那就不是补帧的问题，而是要消灭整个中间态（→ K36 的 `SW_HIDE`）。凡「闪」类报障，先量时长，再选方案 |
| K42 | 列表右侧出现一条 16~17px 的蓝色竖块，压在内容上 | 外框块**整块铺 `FRAME` 底色**，而 ListView 被藏掉原生滚动条后那块区域不重绘，底色就从缝里露出来 —— 宽度正好等于原生条（16~17px）。正解：外框**不要铺底色**，改「`WHITE` 白底块 + 四边各一条 1px `FRAME` 线」，让露出来的永远是白底（同《打开方式清理》1.4.0；框线画法见 §10.4、与 K27 配套） |
| K43 | 刚切到一个页、内容明明超屏，自绘滚动条却不出现；滚一下才出来 | `LVM_GETCOUNTPERPAGE` 在 `Move` 之后立刻取，拿到的是**过期值**（还按旧高度算）；若 `ScrollToRow` 里再多调一次 `Measure`，两次结果互相打架。正解：**可视行数只在一个地方算** —— `Layout()` 里 `Move` 完列表之后再取一次，别处一律读缓存，`ScrollToRow` 只管按缓存算位置 |
| K44 | 滚轮滑动时窗口闪一下（内容没超屏也闪） | 重绘用了 `RedrawWindow(..., RDW_INVALIDATE\|RDW_ERASE\|RDW_UPDATENOW)`：`RDW_ERASE` 会先把整块擦成白底再画，且**位移为 0 时也在重画**。正解：去掉 `RDW_ERASE`；首行没变就直接 `return`；列表加 `LVS_EX_DOUBLEBUFFER`（0x10000） |
| K45 | 右键菜单不跟鼠标，固定弹在屏幕右下角 | AHK v2 的签名是 `Menu.Show([Callback, X, Y])` —— **第一个参数是回调不是 X**，写 `Menu.Show(, x, y)` 才是指坐标；直接 `Menu.Show("", x, y)` 会把 `""` 当回调、把 x 当 Y。正解：**`Menu.Show()` 不传任何参数**，让它自己跟着光标弹；确实要指定位置才用 `Menu.Show(, x, y)` |
| K46 | 列表上右键，菜单根本不弹（`WM_RBUTTONUP` 一次都收不到） | ListView 在右键按下后会进入内部 `DragDetect` 循环，抬起消息在循环里被吃掉，`OnMessage(0x205)` 收不到。正解：菜单挂在**按下**（`WM_RBUTTONDOWN` 0x204）时弹；又因为模态菜单会卡住重绘，要用 `SetTimer(cb, -30)` 异步弹，别在消息回调里直接 `Show` |
| K47 | 最大化之后自绘列头带（或标题带）宽度不跟随，右边空一截 | 窗口尺寸变了，`ListView` 会自己重排，但自绘的那几条色块不会。整窗 `Redraw()` 能修但**整窗闪**。正解：`OnSize` 里把每个自绘控件**逐个 `InvalidateRect(hwnd, 0, false)`**（第三参 false = 不擦背景），再统一走一次 `Layout()` |
| K48 | 用 `Gui.Move()` 设了 672×520，窗口却矮了一截、状态条被压扁 | `Gui.Move(x, y, w, h)` 的 `w/h` 是**外框**尺寸，`Gui.Show("w672 h520")` 才是**客户区**尺寸，两者差一圈标题栏与边框（实测客户区被压成 656×178）。正解：需要精确客户区就用 `Show` 设尺寸，或按 `AdjustWindowRectEx` 换算；窗口尺寸相关的断言一律量客户区 |
| K49 | 列表滚动后**零星几行的文字只剩上半截**（勾选框一起缺） | 自定义绘制在 `CDDS_SUBITEM \| CDDS_ITEMPREPAINT` 阶段返回了 `CDRF_NEWFONT(2)`，可那里只 `NumPut` 改了 `clrText`、**从未在 hdc 里 SelectObject 换过字体**。返回 2 等于告诉控件「字体已换」，控件随后按它自己认定的字体重排该行，行内文字被行边界裁掉一截。**只改颜色就返回 `CDRF_DODEFAULT(0)`**；真要换字体，必须先在 hdc 里选好字体再返回 2 |
| K50 | 同上症状，或滚动后行与行交界处留残影 / 半截字 | 竖向滚动走 `LVM_ENSUREVISIBLE` 时，控件靠位块拷贝搬旧像素、新露出的行由它自己补画，两者交界处就会留下半截。两道一起上：① `LVM_SETEXTENDEDLISTVIEWSTYLE(0x1036, 0x10000, 0x10000)` 开 `LVS_EX_DOUBLEBUFFER`；② 每次滚动动作末尾对列表 `InvalidateRect(hwnd, NULL, FALSE)` + `UpdateWindow()` 整块重画（`FALSE` = 不擦背景，才不会闪）。**第二参必须传 NULL**：传一个全 0 的 RECT 是「空区域」，什么也不作废，重画悄悄失效 |
| K51 | 列表滚动时右缘/底部冒出原生灰条残影（`#808080`/`F0F0F0`），「藏 + 擦」补多少版都差一拍 | **原生滚动条的像素画在 ListView 非客户区（NC）**：`ShowScrollBar(FALSE)` 只摘样式位、不擦已画进 NC 的灰像素；`InvalidateRect(lv, NULL, FALSE)`/`UpdateWindow` 只作废**客户区**，永远碰不到 NC 那 17px；comctl32 每次重算滚动范围（`Move`/`Add`/`Delete`/`ModifyCol`/`LVM_ENSUREVISIBLE`/滚轮）都把 `WS_VSCROLL\|WS_HSCROLL` 置回并重画 NC 灰条——「出现后再藏再擦」是死结，永远慢一拍（软件卸载 1.0.11→1.0.21 十版补刀全失败，含 `SWP_FRAMECHANGED`、`CoverNative`、`trackBg` 底衬，方向都错）。**正解：给 ListView 挂 `WM_NCCALCSIZE` 子类，在 NC 空间计算到达时临时摘掉 `0x00300000` 样式位再走默认计算、算完恢复——原生条分不到 NC 空间、一个像素都画不出来**；滚动走 `SetScrollInfo`，与滚动条视觉是两套机制，`LVM_ENSUREVISIBLE`/滚轮/键盘照常。`SetWindowSubclass` 必须在第一次 Layout/填表之前挂，`OnGuiClose` 里 `RemoveWindowSubclass` 摘除（K21）；旧的 `HideNative/Repair` 可留作保险丝。**关键判据：自绘条画在 ListView 右侧外、原生条在内侧，两块不重叠，所以任何客户区里的底衬/色块/补擦都盖不到原生条——别在客户区找解，要到 NC 计算这一层动手**（这是 Win32「hide scrollbar but keep scrolling」的标准答案） |

## 取证方法学（原《开发指南》§6.1，编号沿用）

门禁会骗人，截图不会 —— 但**读数方式错了的截图一样会骗人**。下面几条都是实打实踩出来的：

- **只看终态 = 白验。** 启动类缺陷几乎都发生在「中间态」：填表、扫描、重排的过程中。
  `打开方式清理` 1.5.2 / 1.5.3 两版都把收尾那一帧擦干净了，终态截图无可挑剔，可填表那
  700ms 里右侧一直挂着原生灰条。**验收必须抓中间态**：定时刻截图 + 逐帧采样。
- **新断言先能红，再信它的绿。** 拿「修复前的代码」跑一次，确认它真的报错。
  当年那条原生条门禁第一版按 `GetClientRect` 算采样带（客户区**不含**滚动条），
  整整错开 16px，对带缺陷的旧代码照样报「0 命中」—— 这种门禁比没有更坏，它给你一个假通过。
- **改哪个控件，就按那个控件的窗口矩形采样。** 判「有没有多出一条 16px 的条」用
  `GetWindowRect`；判「客户区里画得对不对」才用 `GetClientRect`。混用必错。
- **`.bf` 快照就是现成的对照组。** 验证门禁时把旧快照里的 `.ahk` 临时换回 `scripts/` 跑一遍，
  跑完再换回来（换之前先 `cp` 一份当前版本到 `.temp`，别把好的覆盖丢了）。
  没有对照组，「新门禁为真」这句话没有依据。
- **逐像素数据 > 目测截图。** 放大裁图的起点若压在行文字上半，会把「裁切伪影」看成
  「控件裁字」。判读截图必须以像素行数据为准（墨迹高度、网格对齐），不靠目测。

三个现成手法：

1. **脚本内打点**——定位「慢在哪一段」。逐条 `FileAppend` 落盘，进程被宿主强杀也不丢：

   ```ahk
   DBG(s) => FileAppend(Format("{:6}", A_TickCount - T0) "  " s . "`n", LOG, "UTF-8")
   ```

   （别用「攒进全局串、退出时一次写」的写法，宿主强杀就全没了。）
2. **逐帧采样**——定位「有没有真的画出来」。`BitBlt` 屏幕 → `GetDIBits` → 逐列判
   「整列 ≥90% 同色且 ∈ {`F0F0F0`, `C0C0C0`}」。周期 8–10ms，命中即存 PNG。
   判据用「**最长连续命中帧数**」而不是总帧数：单帧 ≈10ms 肉眼看不见，真 bug 是连续几十上百帧。
3. **定时刻整窗截图**——确认「用户到底看到了什么」。起进程 → 等窗口 → `sleep(延迟)` →
   整窗 `BitBlt` → 存 PNG。启动类问题取 0.8 / 1.2 / 1.6 / 2.0s 各一张，足够钉住中间态。

**读图硬规矩：状态栏 / 进度文字是阶段的指纹，先定阶段再看像素。**
状态栏停在「正在扫描 · 15/15」而列表是空的 —— 那**不是**扫描阶段，是**填表阶段**。
顺序反了会得出完全相反的结论。

**数值化读图**（不靠肉眼、可复述）：沿某一行/列扫描颜色分段，例如

```
y=300:  x16 B7C8E0 | x17..1065 F7F9FC | x1067..1082 F0F0F0 | x1083 B7C8E0
```

16px 一段的 `F0F0F0` 就是原生条；它夹在两条 `B7C8E0`（我们的框线）之间，说明是**列表自己的**
滚动条，不是外层容器的。本机没有 PIL，纯 python 解 PNG 即可：zlib 解 `IDAT` +
逐行反过滤（None/Sub/Up/Average/Paeth），40 行代码，够用。

**环境噪声要认出来**：抓图和实机测试都受前台窗口影响。`SetForegroundWindow` 可能被系统拒绝，
被别的窗口盖住时 `BitBlt` 抓到的是别人的画面 —— 表现为「调色板断言报出一整片陌生色」
「满宽像素数突然骤降」。这类「数值离谱」的失败先怀疑遮挡，别急着改代码。
另外：自己 Popen 出来的 GUI 脚本窗口跑在隔离桌面上，`PrintWindow(hwnd, hdc, 2)` 能抓到内容，
但 **BitBlt 抓屏幕坐标必须先 `SetProcessDpiAwareness(2)`**，否则 `GetWindowRect` 返回逻辑
坐标而屏幕是物理像素，抓到的是错位的别人窗口；`WM_MOUSEWHEEL` 发给**焦点**窗口而不是
光标下的窗口，测滚轮时必须先点一下列表把它激活，不动再重试一次。
