它是什么

AHKDeck 是一个给 AutoHotkey v2 脚本用的工作台：把散落的脚本收进一个窗口， 统一地运行、停止、编辑、看报错，并把各个脚本的托盘菜单合并到一处。

它是脚本的管理与开发环境，不是脚本本身，也不是一个通用编辑器。脚本内容由 AutoHotkey v2 编写，AHKDeck 负责把它们组织起来、跑起来，并让 AI 能安全地参与编写和验证。

  • 每个脚本在自己的进程里运行，互不干扰；一个脚本出错不会拖垮其它脚本或工作台。
  • 关闭窗口通常只是隐藏到托盘，脚本继续运行；要真正退出用托盘菜单或 --quit。
  • 随包带官方内核，编译出的 exe 在没装 AutoHotkey 的 Windows 机器上也能直接运行。

能做什么

脚本管理

  • 把 .ahk 放进程序旁的 Scripts\，列表里就会出现；可运行、停止、重启、编辑、删除。
  • 删除是移到 temp\deleted\，不是永久抹掉；运行中的脚本会先停止，占用快捷键一并释放。
  • 列表按脚本名升序排列，运行中的脚本单独标注，状态栏显示总 CPU / GPU / 内存占用。

运行与诊断

  • 内置编辑器可保存、查找替换；运行回执与内核报错显示在控制台。
  • 报错带行号、那一行原文、调用函数与调用链，不用再对着弹窗猜。
  • 各会话日志写在 temp\logs\。

托盘合并

各脚本自己的托盘图标会被收起来，菜单汇集到工作台的「运行中」子菜单——这是本项目从一开始就坚持的硬需求： 托盘不再被十几个脚本图标占满。

一键编译为 EXE

行右键或「脚本 > 编译为 EXE」，选好位置和名字，得到一个可独立分发的 exe。产物直接复制随包内核写入脚本资源， 不依赖机器上是否装了 AutoHotkey，也不需要额外的打包工具。

获取与订阅

「脚本 > 获取脚本…」看官方脚本库；「订阅…」里填一份同格式的 scripts.json 地址， 就能把别人的脚本集并进同一个列表，每行「来源」列标明是官方还是哪个订阅。

运行期产物收敛

程序旁只有一个 temp\：logs\、 backups\、work\、deleted\。 「设置 > 选项…」里选保留时长（永不 / 7 / 30 / 180 天，默认 30），启动时和改设置时各清理一次。

快速上手

  1. 解压后双击 AHKDeck.exe。第一次运行会建好 Scripts\ 和 temp\。
  2. 点「脚本 > 获取脚本…」下载一个官方脚本，或者把自己的 .ahk 复制进 Scripts\。
  3. 在列表里选中它，点「运行」。有托盘菜单的脚本，菜单会出现在工作台托盘图标的「运行中」子菜单里。
  4. 改脚本用内置编辑器；保存后重新运行即可生效。报错看控制台，完整日志在 temp\logs\。

命令行也支持一些常用操作：

命令作用
AHKDeck.exe --version打印版本后退出
AHKDeck.exe --run Scripts\某脚本.ahk运行一个脚本
AHKDeck.exe --journal --run …逐行输出 JSON 事件，便于排查
AHKDeck.exe --quit通知运行中的工作台退出

「脚本 > 获取脚本…」打开下载窗口，列表来自官方仓库的 scripts.json。首次打开读随包清单， 点「刷新」才联网。选中一行点「已下载 / 升级」即可安装或更新到 Scripts\。

版本历史

脚本详情窗里有一行「历史版本」，给出 Gitee | GitHub 两个可点击链接，指向该脚本的版本清单； 清单里每个版本都有对应下载地址。两个链接都与当前选用的下载源无关，随时可点。

「设置 > 选项…」里的官方下载源是一个统一开关，同时决定脚本清单、脚本下载、宿主更新清单和更新包从哪个镜像取。

官方脚本仓库： Gitee · GitHub。 请只从这两个地址获取，避免第三方改包。

自己开发脚本

官方脚本都是一份纯 AHK v2 源码，可以用原版 AutoHotkey v2 独立运行，功能不依赖宿主私有 API。 想照着做，按这个顺序看随包的 docs\：

  1. 先定形态、选范本：找一份和你想要的窗口最像的现成脚本源码，照它的结构起步。这一步比读任何规范都有效。
  2. 读 脚本开发流程.md：从建骨架到自测、实机验证、出货的完整步骤。
  3. 读 开发指南.md：目录约定、头部元数据、版本规矩、命名、产物放在哪里。
  4. 写界面时读 UI规范.md：八色配色、字号、尺寸令牌、控件画法。
  5. 具体控件照 UI组件手册.md；遇到诡异现象查 UI踩坑.md。
  6. 让 AI 帮忙时读 MCP接入.md：把工作台挂到支持 MCP 的 AI 客户端，AI 能写脚本、跑脚本、读结构化报错、量界面。

几条硬规矩

  • 脚本产生的任何文件（配置、备份、报告、自测输出）都放进与脚本同名的文件夹，不要摊在脚本旁边。
  • 不自设全局热键；入口走托盘菜单，这样宿主才能把图标合并起来。
  • 只支持 Windows 10 / 11 与 AutoHotkey v2。
  • 版本按三档递增：第一位＝破坏性改动，第二位＝用户可见新能力，第三位＝修复与打磨。

让其他人也用上

有三种由轻到重的方式，按需选择：

1. 直接分发源码或编译后的 exe

单个 .ahk 拷给别人即可（对方需装 AutoHotkey v2）；或用「编译为 EXE」生成一个独立 exe， 对方双击就能跑，什么都不用装。

2. 做成一个订阅源

把你自己的脚本按官方仓库的形状放进一个目录，生成同样格式的 scripts.json， 放到任意 HTTPS 地址；别人在「获取脚本 → 订阅…」里填这个地址就能订阅，列表里会标明来源。

3. 发布到 Release

官方仓库对每个脚本的每个版本各建一个 release，tag 形如 <英文id>-<版本>； 清单里写下载地址与版本历史链接，两端镜像各发一份。工具和规矩见脚本仓库的 README 与开发指南。

所有链接都是 HTTPS 地址；宿主只接受 HTTPS，无效的历史链接会被忽略，但不会让整个脚本失效。

★ 让 AI 通过 MCP 帮你写脚本（复制这段话就能开始）

你不需要懂 MCP 协议，也不用记工具名。把下面这段话发给任何支持 MCP 的 AI， 它会自己去读随包文档、连上 AHKDeck、按规矩把脚本写出来，并且自己运行验证。

可直接复制发给 AI 的话 
我有一个 AHKDeck 项目，就在 <项目所在文件夹，留空则用当前工作目录>，这是 Windows 上管理 AutoHotkey v2 脚本的工作台，可以通过 MCP 让你读写脚本、运行脚本、看报错、量界面。

请先打开 exe 同级目录的 docs 文件夹，仔细阅读这些文档，并严格遵守里面的准则：
- 使用说明.html（整体功能）
- 脚本开发流程.md（怎么从零做一个脚本）
- 开发指南.md（目录、头部、版本、命名、产物放哪里）
- UI规范.md、UI组件手册.md、UI踩坑.md（如果脚本有界面，这几个必须看）
- MCP接入.md（怎么把你接到 AHKDeck 的 MCP 上）

接好之后，先告诉我你看到了哪些工具、准备怎么做，等我确认再动手。

我需要的脚本是这样的：<用大白话描述功能，越具体越好，比如「按 Win+Q 把当前窗口置顶，再按一次取消」>。

另外请遵守：脚本产生的文件放进与脚本同名的文件夹；不要自设全局热键，入口走托盘菜单；只支持 Windows 10/11 和 AutoHotkey v2；写完自己跑一遍、读报错、确认没问题再告诉我。
红色标注的 <...> 就是需要你按自己情况改的地方：项目路径可以直接写，也可以留着让 AI 用当前工作目录；功能描述换成你真正想要的。其余文字原样发给 AI 即可。AI 连上后如果先问你问题，这很正常——它在确认需求边界。

这段话为什么这么写

  • 写明文档位置和「仔细读、守规矩」，AI 就不会凭记忆乱写，也不会把配置文件摊在脚本旁边。
  • 要求它先报计划再动手，你可以在它改文件之前纠偏。
  • 要求它自己运行验证，把「写 → 跑 → 读错 → 改」的闭环交给 AI，你只看结果。

接好之后具体能做什么、背后是什么机制，看下一节；要改配置细节，去 docs\MCP接入.md。

AI 接入能做什么

AHKDeck 自带一个标准 MCP stdio 端点，不绑定任何特定 AI 或 Agent。 任何支持 MCP stdio 的客户端，只要能配 command 和 args 两个字段就能接进来：

  • command 指向 AHKDeck.exe
  • args 为 ["--mcp-stdio"]

接入后，AI 可以列脚本库、读写编辑区、运行脚本、拿内核原话的报错、读会话输出、停止脚本； 还能量出脚本窗口的控件树与像素色，改完自己验证——于是「AI 写 → 跑 → 读错 → 改 → 再跑」 这条闭环不用人复制粘贴。

不确定某个 AHK 函数的签名或参数含义时，AI 可以用 lookup_help 查随包离线索引， 不必凭记忆。详细配置与各客户端示例见 docs\MCP接入.md。

程序本身不内建聊天面板——模型和修正循环由你选的 AI 客户端负责，AHKDeck 提供工具与可见的编辑区。

常见问题

关掉窗口后脚本还在跑吗？

在。标题栏关闭通常只是隐藏到托盘；要彻底退出，用托盘菜单的退出项或 --quit。

托盘图标去哪了？

被工作台收拢了。点工作台托盘图标，「运行中」子菜单里能找到各脚本原来的入口，功能不变。

下载的脚本装到哪里？

程序旁的 Scripts\。脚本自己产生的文件则放在 Scripts\<脚本名>\。

脚本报错只有一行文字怎么办？

看控制台：那里有行号、出错那行原文、函数名和调用链。完整日志在 temp\logs\。

能离线用吗？

可以。运行、编辑、编译都不联网；只有「刷新」脚本列表、下载脚本、检查更新时才需要网络。

官方脚本能独立运行吗？

能。装上原版 AutoHotkey v2 后双击即可，不需要 AHKDeck——工作台只是让管理更省事。
