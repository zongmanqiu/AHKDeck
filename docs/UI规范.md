## 10.1 适用范围与环境前提

- **适用**：官方脚本用 `Gui()` + 原生控件（`Text` / `Edit` / `ListView` / `DateTime` 等）
  建的窗口。**不适用**：宿主 FLTK 自绘 UI（另一套 `Theme.h` 的 `TextSize()` / `SubTextSize()`
  与 `.main/test/ui_gate/check_chrome_kit.ps1` 的 R7 门禁；FLTK 用像素、AHK 的 `s` 是磅，
  **单位不同，禁止互相照抄数值**）、托盘菜单、无 GUI 脚本、第三方脚本。
- **为什么必须自绘**：m192 后脚本跑在各自的独立子进程里，内核自带 comctl32 **v6** manifest；
  早期「宿主无 manifest、控件退回经典 3D」的说法已经不再描述当前运行形态。自绘仍是硬要求，
  但理由与 manifest 无关：本规范封版的八个色值与 1px 框线，原生主题给不出来
  （`SetWindowTheme` 只切浅/深两套外观，见《UI组件手册》）；控件的边框、日期右侧按钮是
  控件内绘，样式位改不掉（K17）；按钮悬停/按下态也没有稳定可靠的画法（K28）。所以「扁平、
  同色、对齐」只能靠四条与主题无关的手段：`WM_CTLCOLORSTATIC` 色块、`-E0x200` 去扩展边框、
  `SetWindowRgn` 裁掉控件内绘区、DWM 染标题栏。
- **验收口径**：**同一份脚本，独立运行与宿主 `--run` 的像素必须一致**。只在一个环境里好看不算过。
- **分发约束**：脚本单文件平铺进宿主 `Scripts/`、按 `scripts.json` 逐文件 raw 下载，
  **不得抽公共 `#Include` UI 库**（多一个文件就破坏分发模型）。统一靠「本规范 + 每个脚本
  复制同一段令牌代码」维持，不靠共享库。
- **像素是唯一发现器**：门禁全绿不等于界面正确。每个窗口都要独立运行与宿主启动各抓一张
  真实截图复核，抓图前清干净残留的 `AutoHotkey` / `AHKDeck` 测试进程；
  **不要杀用户自己开着的 AHKDeck 主程序**。取证手法见 [`UI踩坑.md`](UI踩坑.md) 的「取证方法学」。

## 10.2 设计令牌（唯一真源，禁止脚本内自造色值 / 字号）

### 10.2.1 颜色

八个色，全部落在同一条蓝色色相上（蓝分量单调递增、明度单调递减）。**不许加第九个。**

| 令牌 | 值 | 用途 | 对白底 | 对 `BG` |
|---|---|---|---:|---:|
| `WHITE` | `FFFFFF` | 输入框、列表、未选中勾选框的内底 | 1.00 | 1.05 |
| `BG` | `F7F9FC` | `Gui.BackColor`、信息行底 | 1.05 | 1.00 |
| `SOFT` | `EBF2FB` | **所有**按钮底、勾选框选中底 | 1.13 | 1.07 |
| `BAND` | `DCE8F7` | 系统标题栏、标题带、列头带、状态条、滚动条槽 | 1.24 | 1.18 |
| `ACCENT_SOFT` | `BFD5F0` | 保留档：唯一「再深一档的浅蓝」，当前**无控件使用** | 1.50 | 1.42 |
| `FRAME` | `B7C8E0` | **所有** 1px 框线与分隔线 | 1.70 | 1.61 |
| `ACCENT` | `6E9BD4` | 滚动条滑块（唯一允许的中等深度色） | 2.88 | 2.73 |
| `TEXT` | `202B3A` | 所有文字（近黑，不是纯黑、不是灰） | 14.30 | 13.56 |

- 对比度 = WCAG 相对亮度比，实测值，可直接引用。**文字只允许 `TEXT`**：压在 `BG` 上 13.56、
  压在 `SOFT` 上 12.69、压在 `BAND` 上 11.53，全档充足；因此「白字对比度 ≥ 4.5」那条老红线
  随白字方案一起作废。
- **大面积不加深色**：整窗最重的一块是 `BAND`（1.24），深色只出现在 1px 线与滚动条滑块上。
  原因是窗口图标是 AHK 官方绿（实测 `448E3A / 7AD974 / 8CF287`，对白 4.06），
  一块 2.88 的大面积蓝就会把图标压掉。`ACCENT` 只许出现在宽 ≤6px 的滑块上。
- **色阶台阶**：白 1.00 → 按钮底 1.13 → 带 1.24 → 保留 1.50 → 线 1.70 → 滑块 2.88。
  相邻档差 1.1–1.4 倍，肉眼能分层但不会跳；`ACCENT` 到 `FRAME` 有个 1.7 倍的大跳，
  正好用来让滑块「浮」在槽上。
- 两张写法别搞混：AHK 的 `Background` / `c` 选项用 **RRGGBB**；DWM 的 `DwmSetWindowAttribute`
  用 **COLORREF `0x00BBGGRR`**（`#DCE8F7` → `0x00F7E8DC`，`#202B3A` → `0x3A2B20`）。

### 10.2.2 字体与字号

字体全窗口唯一：**`Microsoft YaHei UI`**。字号只准四档，其中 `GLYPH` 不是文字档：

| 档 | 值 | 用在哪 | 配套控件高 | 加粗 |
|---|---|---|---|---|
| `BODY`（基准） | `s10` | 按钮、输入框、列头、列表、字段、信息行、状态条 —— 一窗 90% 的字 | 26 / 28 / 30 | 仅列头与区块标题 |
| `CAPTION` | `s9` | 日期框三角 `▼▲`、密集说明、脚注 | 11 / 13 / 24 | 禁止 |
| `GLYPH` | `s11` | **只给勾形 `✓`**，不给任何文字 | 14 | 必须 `Bold` |
| `HEADING` | `s12` | 672 以上大窗的区块标题；420 小窗不用 | 32–34 | `Bold` |

- **默认一律 `s10`**，加字号不是「更清楚」，是「更吵」。同一窗口**最多 2 档文字**且必含 `s10`。
- **加粗只给列头与区块标题**：`SetFont("s10 Bold", ...)` 包住，写完立刻
  `SetFont("s10 Norm", ...)` 还原。按钮、输入框、列表、状态条一律 `Norm`。
  禁止用 `Bold` 表达「重要」—— 重要性用位置和文案表达。
- 只有 `s10` 档做过完整像素实证（含输入框 `EM_SETRECT top=2`、全部控件高、列宽）。
  换档**必须**重新抓图核垂直居中，**不得照抄 `top=2`** 与 §10.3 的坐标表。
- `s11 Bold` 的勾形是特例：14px 方块里 `s10` 的 `√` 只有 1px 细线看不出形状，
  `✔`（U+2714）会糊成一团，只有 `✓`（U+2713）+ `s11 Bold` 笔画约 2px，与系统勾选框最接近。

### 10.2.3 尺寸与间隔

| 名 | 值 | 说明 |
|---|---:|---|
| `EDGE` | 16 | 左右边距，所有内容行起点 |
| `TOP` | 12 | 首行距客户区顶 |
| `ROW_GAP` | 4 | **同组**字段行之间（连续表单行） |
| `BLOCK_GAP` | 6 | **不同语义区块**之间（字段组 / 列表区 / 操作行 / 状态条） |
| `INLINE_GAP` | 8 | 同一行内控件之间、列之间、按钮之间 |
| `H_FIELD` | 26 | 标题带、列头、字段行、字段行里的勾选框 |
| `H_ACTION` | 28 | 按钮、输入框、操作行的勾选框 |
| `H_STATUS` | 30 | 状态条 |
| `INSET` | 1 | 原生控件相对外框的内缩量（也就是线的宽度） |
| `LINE` | 1 | **所有**框线与分隔线的粗细 |
| `CELL_PAD` | 6 | 区块内文字相对内缘的左内缩（`16 → 22`） |
| `STATUS_PAD` | 12 | 状态条文字左内缩 |
| `BTN_PAD` | 16 | 按钮文字左右各留白 |

- `H_FIELD` 与 `H_ACTION` 差 2px 不是随手写的：字段行里放的是 `DateTime`（控件实高 28、
  外框帧 26，靠上下各露 1px 收边），操作行里放的是 28px 的按钮与输入框。
  凡是需要「帧 + 内缩 1px」的行用 26，直接放按钮的行用 28。
- 所有尺寸都是整数像素，不用百分比、不用 `%A_ScreenWidth%`、不随 DPI 缩放另算。

## 10.3 版式：网格、垂直节奏、水平规则

### 10.3.1 五条通用规则

1. **宽度**：`窗口宽 = 行宽 + 2×EDGE`，`行宽 = 客户区宽 − 32`。所有内容行从 `x16` 起、
   宽 `行宽`，**行内加和必须精确等于行宽**，右侧不留死区。
2. **按钮宽**由文字定：`宽 = 文字实际宽 + 2×BTN_PAD`。`s10` 四个汉字约 52px → **84**。
   行里有弹性控件（输入框）就让它吃余量；**没有弹性控件时，余量留在按钮组左侧**，
   整组右对齐到行右缘。不要为了铺满把按钮撑宽（K25）。
3. **垂直节奏**：`TOP` 起 → 同组行间 `ROW_GAP` → 换语义区块 `BLOCK_GAP` →
   带标题的区块内部 `0` → 状态条前 `BLOCK_GAP` → 状态条贴窗口底。
   窗口高 = 状态条底边 y + `H_STATUS`。
4. **同排同高**：同一行的控件 `y` 与 `h` 必须完全相同；所有文字控件**固定 h + `+0x200`**
   （`SS_CENTERIMAGE`）垂直居中。不要让控件靠内容撑高。
5. **对齐**：同一列的所有控件共用同一条左缘（误差 ≤1px）；区块内文字统一比内缘缩进
   `CELL_PAD`；左右两边不出现「半格」偏移。

## 10.4 框线：只有两种合法画法

界面上每一根 1px 线，都必须能用下面两条之一解释。找不到出处的线（灰边、凹槽、阴影）一律是 bug。

1. **父块露线**：先铺一块 `FRAME` 底块，再把原生控件放上去并四周内缩 `INSET = 1px`。
   控件自己不带边框（`-E0x200`），露出来的那一圈就是线。
   底块与控件的关系是「底块在外、控件在内」，**底块绝不外扩**（外扩 1px 会让列表框比表头宽，K7）。
2. **色块当线**：需要单独一条分隔线时，用 `1px 宽 / 1px 高` 的 `FRAME` 色块，
   `x`（或 `y`）与相邻内容对齐、长度与相邻内容相同。**不要**用 `-` 字符、`Border` 样式、
   `WS_BORDER`、`WS_EX_CLIENTEDGE` 去画。

**带标题的列表区做成一个整体框**（K27）：外框块从标题带**顶边**一直包到列表**底边**，
标题带与 `ListView` 都内缩 1px 落进同一个框里，四边共用同一条线。
若标题带自己铺一条浅蓝、列表再自带一圈边框，两条边互不相干，读起来是「一块色条压在一个框上」。

**一条线只画一次**：相邻两块共用同一条边。两块各自带 1px 边并排，视觉上就是 2px，
在 1px 的世界里非常显眼。同理，`FRAME` 只做线，`BAND` 只做面 —— 不要用 `BAND` 画线，
也不要用 `FRAME` 大面积铺底。

**线的粗细只有一档**：`LINE = 1`。没有 2px 强调线，没有虚线，没有圆角。

## 10.6 文案与状态

- **按钮**：2–4 个汉字的动词短语（`更新时间` / `清空列表` / `选择文件` / `复制全部`），
  **不加省略号**、不加箭头、不加图标。两个字的动作不成词时才凑四字。
- **标题带 / 列头**：名词或名词短语，2–4 字（`时间类型` / `路径` / `算法` / `哈希值`）。
  列头与列表内容同名词，不写解释。
- **状态条**：事实 + 分隔符 `·`，中英数字间不空格。
  例：`拖入 3 个路径`、`拖入 3 个路径 · 共 12 项（文件 10、文件夹 2）`、`就绪`。
  **不写指令句**（「请拖入文件」），不写感叹号，不放进度动画。
- **信息行**：只写算完才有的事实；未算完写空或写「未选择文件」这类中性状态。
- 中文补充说明用**全角括号**（`包含子文件（夹）`），与正文同一字体。
- 数字与单位之间不加空格（`12 项` 的「项」是全角，`84px` 只在规范里出现，界面不写单位）。

## 10.7 不做的事（黑名单，别反复试）

| 不做 | 原因 |
|---|---|
| 按钮悬停 / 按下变色 | 自绘色块的重绘时机不受控，四条路实测全堵（K28）。状态反馈只用系统控件自带的 |
| 按钮分主次（主按钮深一档） | 中蓝描边 + 浅蓝底配近黑字发闷显脏；主次交给位置与文案（K26） |
| 系统 `Button` / `CheckBox` / `StatusBar` / 原生滚动条 / 原生列头 | 原生外观给不出封版色值与 1px 框线，边框/日期按钮还是控件内绘（§10.1、K17） |
| 原生 `DateTime` 的边框与右侧按钮 | 控件内绘，样式位改不掉，必须裁（K17） |
| 自绘标题带 | 系统标题栏已经染成同一色，再叠一条是冗余 |
| 新的颜色 / 新的字号 | 令牌表已封版；同色相第六条台阶没有语义，只会变脏 |
| 用 `Bold` 表达重要 | 重要用位置表达；`Bold` 只给列头与区块标题 |
| `#Include` 公共 UI 库 | 破坏单文件分发模型（§10.1） |
| `SetWindowTheme` / `SetThemeAppProperties` 假装扁平 | `SetThemeAppProperties` 本就是默认全开，`SetWindowTheme` 只切浅/深两套，给不了任意颜色（K2） |
| 圆角、阴影、渐变、2px 强调线 | 与 1px 线的体系冲突，一半对一半错更难看 |
| 靠 `WM_SETREDRAW` 遮原生滚动条、靠 60ms 定时器补刀 | 前者压不住非客户区，后者在长任务里根本不跑（K36/K38）。要么填表期 `SW_HIDE`，要么别用自绘滚动条 |

## 10.8 代码组织

- **令牌以「注释头 + 字面量」出现**，因为不能抽库。每个窗口在 `BuildGui()` 上方留一段：

  ```ahk
  ; 版式照 UI 规范 §10：客户区 420，内容行 x16 w388（420-16*2）；同排控件同 y 同 h，
  ; 文字控件固定高 +0x200 垂直居中；状态条铺满窗口底，caption 由 DWM 染成同一个 #DCE8F7。
  ```

  下面所有坐标直接用字面量（`"x16 y12 w388 h26"`），**不要**为了「优雅」去 `Format()` 拼串 ——
  字面量才能在截图里逐字比对。色值同理：`BackgroundDCE8F7` 这样内联，不要建 `cBand := "DCE8F7"`。
- **类声明必须在 auto-execute 调用之前**（K18）。顺序固定：
  `全局变量 → class FlatCheck / class FlatScroll → 工具函数 → BuildGui() → BuildGui() 调用 → return`。
- **全局变量**：窗口 `gGui`、控件 `gXxx`（`gList` / `gStatus` / `gBtnApply` / `gChkRec`）、
  集合 `gSeen`。`BuildGui()` 里 `global` 一行声明，不要逐个 `global x`。
- **工具函数按控件命名**：`FlatButton` / `MakeDateField` / `MakeTimeField` / `ClipField` /
  `PaintCaption` / `SetEditRect`，复制时保持同名，方便跨脚本 grep 到出处。
- **自绘控件自己管事件**：`FlatCheck` 内部挂 `Click`，外部只 `OnEvent("Click", cb)`；
  不要在 `BuildGui()` 里对三层色块逐个挂回调。
- **定时器与资源必须能停**：`FlatScroll.Stop()` / `Hover` 类做法一致 —— `OnEvent("Close")`
  里先 `Stop()` 再 `Destroy()`（K21）。
- **函数体不要超过一屏**：`BuildGui()` 按区块空行分段（标题带 / 字段行 / 列表区 / 操作行 / 状态条），
  每段前一行注释说明这块是什么。

## 10.10 落地策略

- **新脚本必守**：写窗口前先复制 §10.5 骨架，令牌、字号、坐标照抄；按 §10.11 逐条自检。
- **存量迁移**（全部完成）：`文件时间修改`（配色与配方出处）、`文件哈希`（672 大窗）、
  `双击防抖`、`夜灯`（FlatTrack 自绘滑块）、`打开方式清理`（列头与滚动条自绘，仅剩 Checked
  勾选框例外）、`防休眠`（纯托盘不适用）、`硬件信息`（多页导航范本）。
  **这里故意不写版本号**：当前样板版本只在开头的参考件表里维护一处，同一份文件不出现两个数；
  各自哪一版收口、改了什么，见脚本自己的 `info/HISTORY.md`。
- **小窗不要照抄 672 坐标表**：只套 §10.2 令牌与 §10.3.1 五条规则，坐标按自己的客户区重算。
  420 窗的完整坐标表在 §10.3.2，可直接当第二份样板。
- **不加 `--audit` 一类的机器门禁**：字号、对齐、配色属视觉属性，静态扫描判不准；
  而「全仓一次扫」还会让改 A 时把 B 的旧账一起翻红。现行准绳是单脚本测试 + 像素复核 + §10.11 人工清单。
