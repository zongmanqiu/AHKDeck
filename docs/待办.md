## 1. 多文件脚本包（zip 分发 + 同名文件夹伴随）

**状态**：✅ 已完成（2026-11-16，m211；m212 改为系统解压）。宿主包安装（中央目录
预校验 + 系统 Shell 解压 + 目录替换）、双扫描

端到端实测通过；尚未有真实包脚本发行，第一个出现时直接走 §9 流程。

### 1.1 背景

现在官方脚本是**单个 `.ahk` 文本**：`scripts.json` 每条给一个 raw 文本地址（钉 tag），宿主
下载后校验 `@name`/`@version` 再 `ReplaceFile` 落盘。有些脚本需要附属文件（DLL、数据表、
自研的取数工具），单文件装不下。

需求：脚本下载支持**包模式**——一个 zip，解开后是 `<名>.ahk` + `<名>/`（同名文件夹，放运行时
需要的文件）。

### 1.2 现状（改之前先读这三处）

| 环节 | 位置 | 现状 |
|---|---|---|
| 清单生成 | `.ahk-v2-scripts/tools/make_index.py` | 每项 `path` 指向 `<名>/<名>.ahk`，`gitee`/`github` 拼 raw 文本 URL |
| 清单解析 | `.main/core/ScriptCatalog.h`（`CatalogEntry`） | 字段 `path/sizeKb/gitee/github`，没有"包"的概念 |
| 安装落盘 | `.main/core/ScriptCatalog.cpp`（`InstallScriptFile`） | 下载到 `targetPathUtf8 + ".part"` → 校验头部 → `ReplaceFile` 覆盖，旧文件留 `.old` |
| 脚本扫描 | `.main/ui/DeckUI.cpp`（`ScanScripts`） | `FindFirstFileW(Scripts\*.ahk)` **平铺不递归** |
| 删除脚本 | 删除逻辑（移到 `temp/deleted/`） | 只搬单个文件，不知道伴随目录 |

### 1.3 要改的地方

| # | 改动 | 文件 | 量级 |

| 1 | 清单加包模式字段：`package`（zip URL）或让 `path` 指向 `.zip` + `entry` 指向包内 `.ahk` | `make_index.py`、`ScriptCatalog.h` | 小 |
| 2 | 安装器支持「下载 zip → 解压到临时目录 → 校验包内 `.ahk` 头部 → 目录整体替换」 | `ScriptCatalog.cpp` | 中 |
| 3 | 引入解压能力：m211 曾内置 miniz，m212 改为**中央目录预校验（自写）+ 系统 Shell 解压**，零第三方库 | `core/ZipPackage.cpp` | 中 |
| 4 | `ScanScripts` 兼容两种布局：平铺 `Scripts\*.ahk` 与目录 `Scripts\<名>\<名>.ahk`；重名要去重 | `DeckUI.cpp` | 小 |
| 5 | 删除/升级时连带处理同名目录（含 `temp/deleted/` 的备份） | `ScriptCatalog.cpp` | 中 |

### 1.4 已定的技术结论

- **用 zip（Deflate），不用 7z**。Win10/11 原生只解 zip；7z 要装 7-Zip 或带 `7z.exe`，等于
  给用户多加一个依赖，与"尽量少文件"的目标相反。
- **包内根目录就是 `<名>/`**，`<名>/<名>.ahk` 是入口，`@name` = 目录名 = zip 名，三者必须一致。
- **禁止**平铺 `<名>.ahk` 与 `<名>/` 同时存在（扫描会重复、升级会打架）。
- 安装仍走现在的安全序列：先落 `.part` → 校验 → 再替换；解压也要先到临时目录，校验通过才
  整体换上去，失败不留半成品。
- 订阅（第三方清单）走同一套解析，天然兼容包模式，不需要单独实现。

## 2. 附：本次调研发现的、与分发无关但值得留档的事实

- GitHub release 直连在部分网络环境不通（实测 `curl` 报 `Failed to connect ... :443`），
  `gh-proxy.com` 一类镜像可用。脚本下载本就双通道（Gitee 主 / GitHub 备），这条只影响我们
  自己抓第三方二进制做调研，不影响用户。
- AHK v2 内核把 `A_PID` 当未赋值变量（实测 2.0.31+补丁内核，运行时报错），脚本里改用其它
  方式取进程信息，别依赖 `A_PID`。

- **C6 第二部分 `ReapLocked` 持锁等 stdout 线程 → 不动，留档**：子进程退出时管道写端关闭，

  只有实测定量到「收割耗时 >1000ms 可复现」才立项，不要顺手优化。

  「必然超时」缺实测支撑。故并入 C6 同裁决、不另立门禁/立项，除非实测反证。
